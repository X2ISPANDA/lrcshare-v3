# 使用要求

LrcShare API 免费开放、无需注册，但服务能力有限（Cloudflare Workers 免费额度 10 万请求/天）。请实现你的客户端时保持克制，让免费服务能长久供所有人使用。

## 客户端标识（User-Agent）

建议在请求中设置 `User-Agent` 头，标识你的应用名称、版本和主页或邮箱，方便我们排查问题：

```
YourApp v1.0 (https://example.com)
```

浏览器环境无法自定义 `User-Agent`（JavaScript 限制该头），可用 `X-User-Agent` 头替代。

## 速率限制

单个 IP 超过 **100 次 / 10 秒** 会被临时阻止（HTTP 429），约 10 秒后自动解封。

- 正常手动使用远达不到阈值
- 批量工具请控制并发、串行处理，别开并发轰炸
- 触发限流时请退避重试，不要立即重试轰炸（否则会持续被拦）

## 请求节流

批量操作（如扫描整个音乐库）建议：

- **顺序请求**：等上一个请求完成再发下一个
- **加延迟**：请求间间隔 200 ~ 500ms

## 缓存

相同 URL 的响应会在 Cloudflare 边缘缓存：

| 类型 | 缓存时长 |
| --- | --- |
| 列表 / 搜索 | 10 分钟 |
| 详情 | 1 小时 |

- **别在 URL 里加时间戳、随机数等噪声参数**，否则命中不了边缘缓存，重复查询都打到源站
- 全量同步请用分页 `limit=100` 逐页拉取，别开并发轰炸

## 目录快照（批量工具必读）

全量同步或批量打标前，先拉一次 [`GET /v1/catalog`](/api/catalog) 拿全库可搜索文本快照（建议本地缓存 24 小时），在本地过滤命中候选再发搜索请求——一次目录请求可替你省掉成千上万次无效搜索。官方 Lyrico 插件已内置此逻辑。

## 空结果是正常业务结果

LrcShare 是小众人工整理曲库，命中是概率事件。`items: []` 不是错误，请做好兜底逻辑，不要重试轰炸。
